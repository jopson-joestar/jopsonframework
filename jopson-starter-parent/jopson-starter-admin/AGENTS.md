# 可复用后台业务

本目录继承[仓库工程规范](../../AGENTS.md)。admin 依赖 core，并作为普通 JAR 向各站点提供后台用例。新增可复用业务按域组织，采用根规范的业务分层。

## 提供方与消费方

- 接入账号与授权能力时，admin 定义账号、组织、角色、资源、授权关系和会话的公共业务契约，负责主体选择、授权生效和撤销语义。core 提供身份接入等通用技术机制。
- 消费站点提供自己的菜单、资源定义、业务角色、默认数据和审批流程。admin 可以管理角色与资源的授权关系。具体单据的归属和状态由拥有该数据的业务域校验。
- 通过公开用例或查询契约接入。消费站点独立维护其账号数据和会话。授权变更时，明确哪一站点的哪些身份、缓存及会话受影响，以及何时刷新或撤销已有授权。

## 装配与验收

- 使用 Servlet 自动配置注册提供给站点的入口，保持对消费站点包名和启动类的独立性。需要初始化业务数据时，由站点选择明确的初始化流程。验证仅引入 starter 的站点可直接启动。
- 消费站点统一使用 `GET /actuator/health` 探活，正常启动时应返回 HTTP 200，且 `status` 为 `UP`。修改自动配置或打包时，核对 starter JAR 中的配置类及自动配置清单。
- 接入授权后，按消费站点验证有效授权、授权不足、撤销后旧会话及跨站数据隔离。用站点实际资源测试“有功能权限但对象不归当前主体”时的拒绝结果。
